# Quarantined legacy behavior

These observations are deliberately **not** rewrite requirements. They remain here so implementation
work cannot settle an ambiguous product question accidentally. “Reject” means preserve the user goal
but do not reproduce the legacy mechanism or failure.

## Recommended rejections

| Observation                                                                           | Recommended rewrite rule                                                      | Evidence                                                                                                                                                                     |
| ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Grade restoration can delete newer grades from unrelated courses and types            | Restore only the selected course and grade type, transactionally              | `flutter:lib/features/grades/grades_card/oral_grade/add_oral_grade_form.dart:65-93`; `flutter:lib/features/grades/grades_card/master_grade/add_master_grade_form.dart:65-93` |
| Written average divides confirmed-grade points by all written-grade records           | Derive averages only from the explicitly accepted grade set                   | `flutter:lib/features/grades/use_grades.dart:58-85`; `react-native:src/features/courses/grades/written/written-grades-row.tsx:13`                                            |
| An empty signature can be confirmed                                                   | Require a non-empty signature or an explicit non-signature approval mechanism | `flutter:lib/features/grades/confirm_with_signature.dart:110-122`                                                                                                            |
| Multiple task paths are written with `;` but read using `,`                           | Store attachments as structured records and preserve multi-image intent       | `flutter:lib/features/tasks/add_task_form.dart:182-199`; `flutter:lib/features/tasks/task_page.dart:38-42`                                                                   |
| Deleting a task leaves copied attachment files behind                                 | Delete or garbage-collect unreferenced local attachment data                  | `flutter:lib/features/tasks/task_page.dart:176-185`                                                                                                                          |
| Flutter week navigation assumes every year has 52 ISO weeks                           | Use calendar-aware ISO week arithmetic, including week 53                     | `flutter:lib/features/schedule/week_page.dart:37-65`                                                                                                                         |
| React Native always queries ISO week 26                                               | Query the displayed/current week                                              | `react-native:src/features/schedule/schedule.page.tsx:70`                                                                                                                    |
| React Native's Android date field does not open a picker                              | Provide a working native date selection journey on both platforms             | `react-native:src/components/date-field.tsx:15`                                                                                                                              |
| Empty class results can crash setup                                                   | Show a recoverable empty/error state without advancing                        | `flutter:lib/features/setup/forms/classes_courses_setup_page.dart:82-94`                                                                                                     |
| React Native setup failures can log silently or bypass course selection after restart | Keep the main app gated until every required setup stage is durably complete  | `react-native:src/utils/missing-info-guard.tsx:17-31`; `react-native:src/app/setup/class-and-courses.tsx:38`                                                                 |
| A missing task or grade may render blank content or an indefinite spinner             | Distinguish loading, not-found, and failure states                            | `flutter:lib/features/tasks/task_page.dart:21-33`; `react-native:src/features/courses/grades/grade.page.tsx:20`                                                              |
| Add Absence can close after a failed React Native mutation                            | Remain in context and show actionable failure feedback                        | `react-native:src/features/absences/add-absence.tsx:48`                                                                                                                      |
| Flutter profile editing can reset an adult student to minor                           | Preserve unchanged profile fields exactly                                     | `flutter:lib/features/setup/forms/profile_setup_page.dart:20-22`; `flutter:lib/router.dart:130-146`                                                                          |
| Holidays are hard-coded to Lower Saxony in 2024                                       | Model the relevant school calendar and date range explicitly                  | `flutter:lib/features/holidays/holidays.dart:27-39`                                                                                                                          |
| A future sync timestamp can trigger refresh through absolute-duration math            | Treat future timestamps as invalid clock state and recover deliberately       | `flutter:lib/features/sync/sync_service.dart:26-34`                                                                                                                          |
| React Native renders master-grade confirmations for a confirmed written grade         | Render confirmation evidence for the actual grade type                        | `react-native:src/features/courses/grades/grade.page.tsx:104`                                                                                                                |
| A zero written average can render as missing                                          | Display numeric zero as a valid value                                         | `react-native:src/features/courses/grades/written/written-grades-row.tsx:47`                                                                                                 |

## Product decisions still needed

| Question                                                                            | Current evidence                                                                                                                             | Suggested default                                                                          |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Should timetable edits apply immediately or commit only on Save?                    | Flutter mutates on every tap/drag although the UI says `Speichern`: `flutter:lib/features/schedule/week_page.dart:137-144`                   | Make Save a real atomic commit and provide Cancel                                          |
| How should timetable entries be deleted?                                            | Flutter uses an unconfirmed drag beyond the grid: `flutter:lib/features/schedule/schedule_entry.dart:106-150`                                | Use an explicit, reversible action; keep drag as an optional shortcut only if discoverable |
| Should courses silently roll into a new semester?                                   | Flutter silently copies them after one second: `flutter:lib/root_page.dart:41-54`                                                            | Offer an explicit “copy previous semester” choice                                          |
| Should old completed and long-overdue tasks remain actionable?                      | Flutter dims them after seven overdue days; source evidence conflicts about tap behavior: `flutter:lib/features/tasks/tasks_view.dart:31-63` | Keep them accessible and introduce an explicit archive model                               |
| Should parent-pending multi-course absences collapse into one card and later split? | Flutter and React Native both group before parent approval and split teacher-specific work afterward                                         | Preserve the shared reason/date grouping but make per-course progression visible           |
| Should stale substitutions remain visible after refresh failure?                    | Flutter retains the last successful list without a staleness indicator: `flutter:lib/models/agenda_store.dart:55-73`                         | Keep cached data but label its freshness and failure state                                 |
| Should setup allow backward navigation?                                             | Flutter models forward replacement only: `flutter:lib/features/setup/helpers/setup_flow.dart:18-31`                                          | Allow safe backward edits before final activation                                          |
| Is licence renewal a product journey?                                               | A Flutter widget exists without a reachable route: `flutter:lib/features/setup/license_renew_page.dart:13-52`                                | Leave out until licence lifecycle requirements are known                                   |
| Should the ten-tap production debug unlock survive?                                 | Flutter unlocks Debug from the About logo: `flutter:lib/features/about/about_page.dart:24-37`                                                | Keep developer controls out of production unless there is a supported diagnostic use case  |
| When and why should notification permission be requested?                           | React Native requests it immediately on main-shell mount: `react-native:src/app/(main)/_layout.tsx:31`                                       | Ask at a contextual moment after explaining value; denial must not impair core use         |
| What should a notification tap open?                                                | React Native only logs it: `react-native:src/app/(main)/_layout.tsx:44`                                                                      | Require a typed destination or no push notification                                        |
| Do timetable/substitution refreshes need a visible staleness policy?                | Flutter suppresses some background errors and keeps cached state                                                                             | Show last-success/failure state without blocking offline use                               |

## Explicitly absent legacy requirements

- The production Flutter app has no implemented task-notification behavior.
- The production Flutter app exposes no external deep-link contract.
- Flutter's database reset helper has no reachable production UI.
- The dormant Flutter licence-renewal widget is not reachable behavior.

Absence does not prohibit a new product feature; it only means archaeology cannot justify it as
parity work.
